# Как устроены окна Сферы

Проверено 19.10.2026 на локальной актуальной сборке клиента.
В `effects` находятся 87 файлов `.ui`, в них 93 блока `windowUI` и 1316 элементов `control`.
Некоторые файлы описывают несколько окон, `sprites.ui` содержит общие изображения.
Картотеку с номерами элементов и свойствами создаёт `generate-catalog.mjs` из выбранного клиента.

## Три слоя

1. `.ui` описывает форму: имя окна, размеры, привязку, элементы, изображения, цвета, шрифт.
2. `.mbc` содержит поведение: создание окна, получение его элементов, обработку событий,
   заполнение текста, запросы серверу и закрытие.
3. Встроенная библиотека клиента хранит шаблоны, создаёт экземпляры и рисует интерфейс.

Изменение `.ui` меняет оформление. Оно само по себе не запускает вход, не обновляет список
персонажей и не восстанавливает обработчики уже закрытого экрана.

## Загрузка и номера элементов

В разборе оригинального 32-битного клиента:

- `FUN_004ba440`: поиск `Effects\*.ui`, чтение блоков `windowUI`, регистрация шаблонов
  по `windowName`. `loadscreen.ui` обрабатывается отдельно.
- `FUN_004d48c0`: чтение свойств окна, затем последовательный обход блоков `control`.
- `FUN_004d16f0`: соответствие `classID` классам Button, Text, Image, Edit, Slot,
  ScrollBar, TextList и другим.
- `FUN_004ce9b0`: сборка изображений `sprite` из одного или нескольких прямоугольников текстур.

Для исследования использован локальный разбор оригинального клиента в Ghidra.
Это свидетельство об оригинальном клиенте; внутреннюю реализацию нового x64-файла оно не доказывает.

Имя файла не обязано совпадать с именем окна. Например, `pickpers.ui` задаёт `pick_person`,
`delete_character.ui` задаёт `del_char_window`.

Номер элемента зависит от его порядка в описании. Сценарии получают его вызовом
`window.control_at(handle, number)`. Удаление и перестановка блоков ломают эти связи,
поэтому редактор сохраняет порядок и изменяет только значения свойств.

## Выбор и удаление персонажа

Проверено на заново разобранном `_pcontrol.mbc` именно из актуальной папки клиента:
разбор модуля `_pcontrol.mbc` с проверкой хэша исходного файла.

- `SelectChar(arg0)`, строка 5273: запускает `SelChar`, задаёт выбранную ячейку `g_893C`
  и флаг активного экрана `g_51C0`. При установленном флаге повторный запуск не происходит.
- `SelChar`, строка 4302: отключает тени, включает стартовую музыку, завершает загрузочный
  экран, открывает `pick_person`, сохраняет его handle в `g_8900`, запускает `TurnMod` и `SelSky`.
- Элементы 25-28, 37-40, 41-56 и другие получаются по номерам. Часть полей динамически
  скрывается и заполняется. Поэтому предпросмотр всех элементов одновременно отличается
  от игрового экрана в конкретном состоянии.
- Удаление открывает `del_char_window`, получает поле 4 и ждёт результат в `g_8AB0`.
  `SetDelCharRes(arg0)`, строка 5289, записывает результат в эту переменную.
- После успешного удаления сценарий вызывает `request_halt(0)`, строка 4814.
  Он не перестраивает список персонажей самостоятельно.
- В конце `SelChar` закрывает `g_8900`, снимает `g_51C0`, удаляет объект предпросмотра
  через `local_00007624` и возвращает тени.

Чтобы вернуть этот экран без полного перезапуска, реализации клиента нужен согласованный
переход состояния: остановить игровые обработчики, закрыть их окна и модели, очистить старые
handles, заново получить данные персонажей, подготовить `_player`, затем вызвать `SelectChar`.
Одно повторное открытие шаблона `pick_person` не выполнит эти действия.
Точный порядок очистки в новом x64-клиенте нужно проверять по его исходникам.

## Потеря связи

`_main.SayTryRestart`, строка 8090 в текущем разборе:

- открывает `connect_message`;
- получает текстовый элемент 3;
- опрашивает события окна;
- событие 1001 от элемента 1 («Подключиться») вызывает `request_halt(0)`;
- закрытие окна и кнопка выхода вызывают `request_halt(-1)`.

Сохранение сессии и смысл `request_halt(0)` реализуются внутри исполняемого файла.
Сообщение автора о новой реализации сохранения сессии не отменяет этот переход в сценарии.
В редакторе оформление окна можно менять, но заменять механизм переподключения он не должен.

## Банк

`npc_banker.UseOwner` получает `_player.GetBank`, затем вызывает `ShowBank` у объекта `_bank`.
Видимый банкир и личное банковское окно принадлежат разным процессам.

`_bank.StartUp` проверяет владельца и отправляет `QueryInit`.
`_bank.WinBank` открывает `bank`; `WinSelcount` открывает `bnk_selcount`.
`RcvUser` обновляет сумму и состояние окна. Регион 12 использует 5-битную команду
и длину массива в 8 бит. Чтение команды как 8 бит было ошибкой незавершённого обработчика.

## Свойства оформления

| Поле                                       | Значение                                                                   |
| ------------------------------------------ | -------------------------------------------------------------------------- |
| `windowName`                               | Имя шаблона для `window.open`                                              |
| `classID`                                  | Тип элемента                                                               |
| `position`, `size`                         | Положение и размер в пикселях                                              |
| `alignWin`                                 | Привязка к краю или центру экрана                                          |
| `windowText`                               | Обычно ключ из `language\strings.ui`                                       |
| `font`                                     | Номер шрифта; новые шрифты из `fonts.cfg` имеют смещение +2                |
| `textcolor`, `focuscolor`, `disabledcolor` | RGB или RGBA                                                               |
| `drawMethod`, `image`, `uncheckedImage`    | Способ рисования и имена спрайтов                                          |
| `texture`                                  | Текстура, четыре координаты источника и четыре координаты назначения       |
| `tcoords`                                  | Номер фрагмента и четыре пары координат текстуры, их нельзя масштабировать |
| `showEffect`, `hideEffect`                 | Эффект появления или скрытия                                               |

Текстуры интерфейса находятся преимущественно в `textures\fx\*.dds`.
Редактор читает DXT1, DXT3, DXT5 и несжатые RGB/RGBA и отдаёт их браузеру как PNG.
Графика клиента при этом не изменяется.

Шрифты `.sfn` содержат растровые метрики и ссылки на атласы символов.
Текущий редактор выбирает существующий шрифт по номеру; он не редактирует атлас и не увеличивает
глобально размер растровых букв. Текст в браузерном предпросмотре приблизительный.

## Что сохраняет редактор

Изменяются только выбранные значения свойств в `.ui`. Окружающий текст, комментарии,
кодировка Windows-1251 и переводы строк сохраняются.
Перед записью сверяется SHA-256 исходного файла, затем создаётся резервная копия.
Откат проверяет, что после сохранения файл не менял другой инструмент.

Редактор не изменяет `.mbc`, исполняемые файлы, базы персонажей или сервер.
Новые значения оформления читаются игрой после перезапуска клиента.
